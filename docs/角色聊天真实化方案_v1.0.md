## 一、背景与问题

### 1.1 现状

穿越圈小程序角色聊天功能目前完全为假数据，无任何真实 AI 调用。

### 1.2 调研发现的问题

| 编号 | 问题 | 位置 | 严重度 |
|------|------|------|--------|
| P0-1 | AI 回复 100% 是 mock | `cloudfunctions/chat/index.js:146` `mockAIGenerate` | 高 |
| P0-2 | 前端取回复字段 BUG | `pages/chat/room.js:196` 取 `data.content`，应为 `data.aiMsg.content` | 高 |
| P0-3 | 角色 ID 三套不一致 | initDB 用拼音 `libai`、chat 云函数用 `fig-libai`、前端传 `f._id`（拼音），导致 `safeGet` 取不到人设 | 高 |
| P1-1 | System Prompt 浪费 | `buildChatPrompt` 构造完整 prompt 但只写库，从未传给 AI 模型 | 中 |
| P1-2 | 云端数据成孤岛 | 云函数写 `chat_messages`/`chat_sessions`，前端只读本地缓存 | 中 |
| P1-3 | 青月系统角色纯前端关键词匹配 | `room.js:265-296` `generateQingyueReply` | 中 |
| P2-1 | 组件定义未使用 | `chat-bubble`、`chat-input-bar` 已定义但 `room.wxml` 未实际使用 | 低 |

## 二、参考方案调研：intelligentmoms 项目

### 2.1 核心结论

intelligentmoms 聊天方案是「**微信云开发 AI 一站式托管**」路线：

- 用微信云开发 AI 扩展 `wx.cloud.extend.AI`（非腾讯云 IM SDK）
- 在腾讯云开发平台后台创建 Agent，前端只传 `botId`
- 鉴权走 `cloud.extend.AI.bot.tokenManager.getToken()` 自动签发临时 token，零密钥管理
- 用 2700 行的 `agent-ui` 组件，支持流式、Markdown、工具调用、语音
- 角色人设在腾讯云后台配置，前端不维护

### 2.2 三种接入模式

| 模式 | 适用场景 | 持久化 |
|------|---------|--------|
| V2 Agent（botId 以 "agent" 开头） | 生产实际使用 | 本地 storage + 服务端 threadId 维护上下文 |
| V1 Bot（普通 botId） | 多会话管理 | 腾讯云 AI 平台存储 |
| model 直连大模型 | 演示用 | 仅前端内存 |

### 2.3 支持的大模型

- 腾讯混元：`hunyuan-open` / `hunyuan-exp` + `hunyuan-lite` / `hunyuan-vision`
- DeepSeek：`deepseek` + `deepseek-r1` / `deepseek-v3` / `deepseek-v3.2`

### 2.4 关键差异（与 timeslip-mini 规则）

- timeslip-mini `app.js` 要求显式指定 envId `cloud1-d0gunpzup215cfd87`
- timeslip-mini AppID 是 `wx515b70782ea1aaf3`，与 intelligentmoms 不同
- timeslip-mini 项目规则要求云函数用 `cloud.DYNAMIC_CURRENT_ENV`，而 intelligentmoms 聊天链路不走云函数

## 三、方案对比

| 方案 | 实现路径 | 优点 | 缺点 |
|------|---------|------|------|
| **A. 完全复刻 intelligentmoms** | 搬运 `agent-ui` 组件，腾讯云后台为每个历史人物建 Agent | 零后端代码、零密钥管理、功能丰富（Markdown/工具/语音） | 需在云后台为 10+ 历史人物分别建 Agent，维护成本高；现有积分/成就/内容安全逻辑要重构；角色人设脱离版本控制 |
| **B. 云函数 + AI 大模型 API** | 保留 chat 云函数架构，在 `modeChat` 中替换 `mockAIGenerate` 为真实 AI 调用 | 业务逻辑完整保留（积分/成就/内容安全）；角色人设代码维护；可控性强 | 需管理 API Key（云函数环境变量） |
| **C. 云函数内调 `wx.cloud.extend.AI.createModel`** | 云函数里用云开发 AI SDK 直连大模型 | 兼顾业务逻辑 + 无需管理密钥；与现有 chat 云函数架构契合 | 需确认云函数环境是否支持 extend.AI |

## 四、推荐方案：B + C 混合

### 4.1 核心思路

保留现有 chat 云函数架构（积分/成就/内容安全/历史人物人设代码维护），把 `mockAIGenerate` 替换为真实 AI 调用。AI 服务用腾讯云开发 AI SDK `cloud.extend.AI.createModel()`，零密钥管理，与项目云开发生态契合。

### 4.2 改动清单

#### 4.2.1 云函数 `cloudfunctions/chat/index.js`

- **新增 `callAI(systemPrompt, history, userInput)`**：用 `cloud.extend.AI.createModel('hunyuan-open')` 调混元大模型，传入 system prompt + 最近 N 轮 history + 用户输入
- **`modeChat`**：把第 146 行 `mockAIGenerate('chat', figureId, content)` 替换为 `await callAI(prompt, history, content)`
- **删除 `mockAIGenerate` / `pickChatGreeting` / `pickChatBody` / `pickPoem`** 四个 mock 函数（约 80 行）
- **修复 `FIGURES` 字典 key**：`fig-libai` → `libai`（与 initDB、前端 `_id` 统一为拼音）
- **异常兜底**：AI 调用失败时返回固定文案 + 错误码，不静默走 mock
- **AI 返回内容二次内容安全检测**：防止模型输出违规内容

#### 4.2.2 前端 `miniprogram/pages/chat/room.js`

- **修复字段 BUG**：第 196 行 `data.content` → `data.aiMsg.content`
- **青月系统角色升级为走云函数**：同 chat 模式，但 system prompt 定义为「穿越圈引导员，介绍兰台/朋友圈/飞鸽/奏折/视频/成就等功能」
- **删除 `generateQingyueReply`** 本地关键词匹配函数（约 30 行）
- **删除 `generateMockReply`** 本地兜底函数（约 10 行）

#### 4.2.3 内容安全检测

- 保留：用户输入仍走 `cloud.openapi.security.msgSecCheck`
- 新增：AI 返回内容也走 `checkText`（防止模型输出违规内容）

#### 4.2.4 本地存储策略

- 维持现状：本地优先，永久持久化
- 云端写入保留（用于换设备/清缓存时可选回读，本期不实现回读）

#### 4.2.5 不改动部分

- 打字机效果（typeEffect）：保留假打字，AI 一次性返回后逐字渲染
- 本地存储 chatSession.js
- 内容安全、积分、成就解锁逻辑
- 聊天室 UI（room.wxml/wxss）
- chat-bubble / chat-input-bar 组件（保持现状）

## 五、AI 服务接入细节

### 5.1 选型：腾讯云开发 AI（混元大模型）

- **SDK**：`cloud.extend.AI.createModel('hunyuan-open')`
- **模型**：默认 `hunyuan-lite`（便宜），关键场景可切 `hunyuan-pro`
- **鉴权**：无需管理密钥，云函数环境自动鉴权
- **流式响应**：本期不做，AI 一次性返回完整回复，前端用 typeEffect 逐字渲染

### 5.2 callAI 函数伪代码

```js
const cloud = require('wx-server-sdk')
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV })

async function callAI(systemPrompt, history, userInput) {
  const model = cloud.extend.AI.createModel('hunyuan-open')
  const messages = [
    { role: 'system', content: systemPrompt },
    ...history.map(h => ({ role: h.role, content: h.content })),
    { role: 'user', content: userInput }
  ]
  const res = await model.streamText({
    data: {
      model: 'hunyuan-lite',
      messages,
      temperature: 0.8
    }
  })
  // 累加流式响应为完整文本
  let fullText = ''
  for await (let event of res.stream) {
    const data = event.json
    if (data.choices && data.choices[0] && data.choices[0].delta) {
      fullText += data.choices[0].delta.content || ''
    }
  }
  return fullText
}
```

### 5.3 青月 system prompt 示例

```
你是「青月」，穿越圈小程序的系统引导员。你的职责：
1. 帮助新用户了解穿越圈的核心功能：兰台人物、朋友圈、飞鸽传书、奏折推演、视频号、成就系统
2. 用古风但亲切的口吻回答用户问题
3. 引导用户体验各功能，但不要长篇大论
4. 不涉及真实的历史知识问答，仅做产品功能引导
```
