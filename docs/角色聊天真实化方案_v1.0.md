## 二、参考方案调研：intelligentmoms 项目

### 2.1 核心结论

intelligentmoms 聊天方案是「**微信云开发 AI 一站式托管**」路线：

- 用微信云开发 AI 扩展 `wx.cloud.extend.AI`（非腾讯云 IM SDK）
- 在腾讯云开发平台后台创建 Agent，前端只传 `botId`
- 鉴权走 `cloud.extend.AI.bot.tokenManager.getToken()` 自动签发临时 token，零密钥管理
- 用 2700 行的 `agent-ui` 组件，支持流式、Markdown、工具调用、语音
- 角色人设在腾讯云后台配置，前端不维护

### 2.2 三种接入模式

| 模式 | 适用场景 | 持久化 |
|------|---------|--------|
| V2 Agent（botId 以 "agent" 开头） | 生产实际使用 | 本地 storage + 服务端 threadId 维护上下文 |
| V1 Bot（普通 botId） | 多会话管理 | 腾讯云 AI 平台存储 |
| model 直连大模型 | 演示用 | 仅前端内存 |

### 2.3 支持的大模型

- 腾讯混元：`hunyuan-open` / `hunyuan-exp` + `hunyuan-lite` / `hunyuan-vision`
- DeepSeek：`deepseek` + `deepseek-r1` / `deepseek-v3` / `deepseek-v3.2`

### 2.4 关键差异（与 timeslip-mini 规则）

- timeslip-mini `app.js` 要求显式指定 envId `cloud1-d0gunpzup215cfd87`
- timeslip-mini AppID 是 `wx515b70782ea1aaf3`，与 intelligentmoms 不同
- timeslip-mini 项目规则要求云函数用 `cloud.DYNAMIC_CURRENT_ENV`，而 intelligentmoms 聊天链路不走云函数

## 三、方案对比

| 方案 | 实现路径 | 优点 | 缺点 |
|------|---------|------|------|
| **A. 完全复刻 intelligentmoms** | 搬运 `agent-ui` 组件，腾讯云后台为每个历史人物建 Agent | 零后端代码、零密钥管理、功能丰富（Markdown/工具/语音） | 需在云后台为 10+ 历史人物分别建 Agent，维护成本高；现有积分/成就/内容安全逻辑要重构；角色人设脱离版本控制 |
| **B. 云函数 + AI 大模型 API** | 保留 chat 云函数架构，在 `modeChat` 中替换 `mockAIGenerate` 为真实 AI 调用 | 业务逻辑完整保留（积分/成就/内容安全）；角色人设代码维护；可控性强 | 需管理 API Key（云函数环境变量） |
| **C. 云函数内调 `wx.cloud.extend.AI.createModel`** | 云函数里用云开发 AI SDK 直连大模型 | 兼顾业务逻辑 + 无需管理密钥；与现有 chat 云函数架构契合 | 需确认云函数环境是否支持 extend.AI |

## 四、推荐方案：云函数统一调用 CloudBase AI

### 4.1 核心思路

保留现有 chat 云函数架构（积分/成就/内容安全/历史记录），把普通角色聊天中的 `mockAIGenerate` 替换为 `cloud.ai().createModel('cloudbase')`。首期使用非流式 `generateText`；青月暂时保留本地引导回复。

角色差异不放前端，也不长期维护在云函数硬编码字典里。前端只传 `figureId`，`chat` 云函数在服务端从现有数据库聚合角色上下文：

```
figureId
  ↓ normalizeFigureId
figures 人物主档
  ├─ figure_passages 相关原文/事件
  ├─ figure_relations 人物关系
  ├─ articles 人物专题文章摘要
  └─ figures.chat_profile 轻量口吻配置（可选新增字段）
      ↓
buildChatSystemPrompt
      ↓
CloudBase AI hy3
```

其中 `figures`、`figure_passages`、`figure_relations` 是高优先级事实来源；`articles` 可作为补充；`videos`、`moments` 更偏产品内容和世界观，不作为权威历史事实来源。

### 4.2 数据源复用设计

> 字段名依据：核查 `shiji/index.js` 的 `normalizeFigure`（`shiji:120-155`）、`figureDetail`（`shiji:218-262`）、`figureRelations`（`shiji:264-297`），以及 `look/index.js` 的 `articlesByFigure`（`look:287-306`）。

#### 4.2.1 `figures`：人物主档

现有 `shiji` 云函数已从 `figures` 集合读取人物详情（`shiji:191` `where({ id: targetId })`），聊天应复用同一主档，避免聊天人设与兰台详情页割裂。

**业务主键是 `id` 字段（纯拼音格式，如 `libai`、`dufu`），不是 `_id`。** 前端 `figure-detail.js:108` 调 `shiji.figureDetail` 返回的 `_id` 被 `normalizeFigure` 回填为 `figures.id` 同值（`shiji:120` `_id: f.id || f._id`），因此前端传给 chat/room 的 `figureId` 实际就是纯拼音。

可直接使用字段：

| 字段 | 用途 | 出处 |
|------|------|------|
| `id` | **业务主键**，纯拼音（`libai`/`dufu`/`simaqian`） | `shiji:191` |
| `name` | 角色姓名 | `shiji:122` |
| `identity` | 角色身份/头衔（如「诗仙」「诗圣」） | `shiji:124` `title: f.identity \|\| ''` |
| `bio_summary` | 生平摘要 | `shiji:125` `bio: f.bio_summary \|\| ''` |
| `keyword_tags` | 人物关键词数组 | `shiji:129` `tags: f.keyword_tags \|\| []` |
| `birth_year` / `death_year` | 生卒年（数值，负数=公元前） | `shiji:136-148` |
| `avatar_url` | 头像 URL | `shiji:128` |
| `src_book` | 主要来源典籍 id | `shiji:215` |
| `dynasty` / `dynastyName` | 朝代编码/显示名 | seed 数据 |
| `star` | 热度排序权重 | `shiji:178` |
| `initial` | 拼音首字母 | seed 数据 |

建议新增服务端字段（当前 `figures` 集合**无此字段**，需补充）：

```js
chat_profile: {
  voice: '沉郁顿挫，语言厚重克制，多从个人困顿推及天下苍生。',
  self_names: ['子美', '少陵野老', '老夫'],
  avoid: '不要写成李白式狂放邀月，不要频繁谈求仙饮酒。'
}
```

该字段只存在数据库和云函数响应中，不下发给普通前端页面，不作为客户端配置。`shiji` 云函数的 `normalizeFigure` 不需要读取此字段。

#### 4.2.2 `figure_passages`：角色知识库主来源

现有 `shiji.figureDetail` 已读取（`shiji:218-262`），外键字段是 `figure_id`（下划线风格，与 `figures.id` 同为纯拼音格式，**无需转换**）。

字段清单：

| 字段 | 用途 | 出处 |
|------|------|------|
| `figure_id` | **外键**，关联 `figures.id`，纯拼音 | `shiji:219` |
| `passage_id` | 原文段落 ID，格式 `bookId/xxx` | `shiji:224` |
| `sort_order` | 排序号 | `shiji:221`、`shiji:249` `.orderBy('sort_order', 'asc')` |
| `event_name` | 事件名 | `shiji:254` |
| `excerpt` | 原文摘录 | `shiji:255` |
| `role` | 人物在该事件中的角色 | `shiji:256` |
| `event_year` | 事件年份（数值） | `shiji:257` |

聊天应优先把这些数据作为"角色专属知识"。例如李白命中《将进酒》《赠汪伦》，杜甫命中《春望》《三吏三别》《茅屋为秋风所破歌》后，两者回答会自然分化。

首期不做向量检索，采用轻量策略：

1. 先按 `figure_id` 取 `sort_order` 靠前的 8 条；
2. 若用户输入命中 `event_name`、`excerpt`、`keyword_tags`，优先保留命中项；
3. 最终塞入 prompt 的条目控制在 5 条以内，每条 `excerpt` 截断到 120-200 字，避免浪费 Token。

#### 4.2.3 `figure_relations`：人物关系

现有 `shiji.figureRelations` 已读取（`shiji:264-297`），双向匹配 `figure_a`/`figure_b`，值为纯拼音。

字段清单：

| 字段 | 用途 | 出处 |
|------|------|------|
| `figure_a` | 关系人物 A 的 id | `shiji:267` |
| `figure_b` | 关系人物 B 的 id | `shiji:267` |
| `relation_type` | 关系类型编码（peer/family/friend/enemy/teacher/student/lord/subordinate/rival/spouse/parent/child/sibling） | `shiji:287` |
| `relation_label` | 关系显示名 | `shiji:289` |
| `description` | 关系描述 | `shiji:291` |

用于回答朋友、师承、君臣、敌友、并称等关系问题。首期取前 5 条：

```js
db.collection('figure_relations')
  .where(_.or([{ figure_a: id }, { figure_b: id }]))
  .limit(5)
```

#### 4.2.4 `articles`：专题补充资料

现有 `look.articlesByFigure` 已读取（`look:287-306`），通过 `figureIds` 数组关联（单值匹配数组字段）。

字段清单：

| 字段 | 用途 | 出处 |
|------|------|------|
| `figureIds` | **关联 figures 的 id 数组**，元素为纯拼音 | `look:197`、`look:209`、`look:287-306` |
| `title` | 标题 | `look:111` |
| `subtitle` | 副标题 | `look:112` |
| `summary` | 摘要 | `look:116` |
| `category` | 分类（figure_truth/perspective/fun_fact） | `look:114` |
| `dynasty` | 朝代编码 | `look:115` |
| `status` | 状态（仅取 `published`） | `look:94` |

查询方式（单值匹配数组字段）：

```js
db.collection('articles')
  .where({ status: 'published', figureIds: figureId })
  .limit(3)
```

用途是补充"看一看"里已经整理过的人物专题，但优先级低于 `figure_passages`。首期只取 3 条摘要。

#### 4.2.5 不建议首期作为事实源的数据

| 集合 | 原因 | 可用方式 |
|------|------|----------|
| `videos` | 偏短视频内容，可能是演绎表达；且 `video_channels.figureId` 用 `fig-` 前缀，与 `figures.id` 不一致 | 可用于口吻/话题补充，不作为史实 |
| `moments` | 偏社交动态，创作属性强 | 可用于产品世界观，不作为权威知识 |
| `video_comments` / `moment_comments` | UGC/拟人评论，事实可信度低；`video_comments.fromFigureId` 用 `fig-` 前缀 | 不进入首期聊天 prompt |

#### 4.2.6 ID 归一化方向修正

**核心修正点**：现有 `chat/index.js:38-42` 的 `safeGet` 把拼音加 `fig-` 前缀去匹配 `FIGURES` 字典，方向反了。v1.2 应改为：

```js
function normalizeFigureId(figureId) {
  const raw = String(figureId || '').trim()
  return raw.startsWith('fig-') ? raw.slice(4) : raw  // 剥前缀，输出纯拼音
}
```

然后用归一化后的 id 去查 `figures.id`、`figure_passages.figure_id`、`figure_relations.figure_a/figure_b`、`articles.figureIds`。`FIGURES` 字典仅作为数据库查询失败时的兜底，key 也应改为纯拼音格式（`libai` 而非 `fig-libai`）。

## 五、AI 服务接入细节

// chat/index.js:67-81（已落地，无需改动）
async function callAI(systemPrompt, history, userInput) {
  const ai = cloud.ai()
  const model = ai.createModel('cloudbase')
  const result = await model.generateText({
    model: AI_MODEL,  // 'hy3'
    messages: [
      { role: 'system', content: systemPrompt },
      ...normalizeHistory(history),  // 见 chat:57-65
      { role: 'user', content: String(userInput).slice(0, 500) }
    ]
  })
  const text = String(result && result.text || '').trim()
  if (!text) throw new Error('AI_EMPTY_RESPONSE')
  return { text, usage: result.usage || null }
}

function normalizeFigureId(figureId) {
  const raw = String(figureId || '').trim()
  return raw.startsWith('fig-') ? raw.slice(4) : raw  // 剥前缀，输出纯拼音
}

// v1.2 新增：聚合角色上下文
async function buildFigureContext(figureId, userInput) {
  const id = normalizeFigureId(figureId)
  const [profile, passages, relations, articles] = await Promise.all([
    loadFigureProfile(id),
    loadFigurePassages(id, userInput),
    loadFigureRelations(id),
    loadFigureArticles(id)
  ])
  return { id, profile, passages, relations, articles }
}

// v1.2 新增：查 figures 主档
async function loadFigureProfile(id) {
  const r = await db.collection('figures').where({ id }).limit(1).get()
  return r.data[0] || null
}

// v1.2 新增：查 figure_passages（取 sort_order 靠前 8 条，再按命中度筛 5 条）
async function loadFigurePassages(id, userInput) {
  const r = await db.collection('figure_passages')
    .where({ figure_id: id })
    .orderBy('sort_order', 'asc')
    .limit(8)
    .get()
  const list = r.data || []
  // 简单命中度排序：用户输入命中 event_name/excerpt 的优先
  const input = String(userInput || '')
  return list
    .map(p => ({ ...p, _hit: input && (p.event_name && input.includes(p.event_name)) || (p.excerpt && input.includes(p.excerpt.slice(0, 20))) ? 1 : 0 }))
    .sort((a, b) => b._hit - a._hit)
    .slice(0, 5)
}

// v1.2 新增：查 figure_relations（双向匹配）
async function loadFigureRelations(id) {
  const r = await db.collection('figure_relations')
    .where(_.or([{ figure_a: id }, { figure_b: id }]))
    .limit(5)
    .get()
  return r.data || []
}

// v1.2 新增：查 articles（figureIds 数组单值匹配）
async function loadFigureArticles(id) {
  const r = await db.collection('articles')
    .where({ status: 'published', figureIds: id })
    .limit(3)
    .get()
  return r.data || []
}

function buildChatSystemPrompt(ctx) {
  const { profile, passages, relations, articles } = ctx
  // 数据库查询失败时走 FIGURES 字典兜底
  const fallback = FIGURES[normalizeFigureId(ctx.id)] || {}

  const tags = (profile && profile.keyword_tags) || []
  const chatProfile = (profile && profile.chat_profile) || {}

  const passageText = passages.map(p =>
    `《${p.event_name || '相关原文'}》${p.excerpt ? '：' + String(p.excerpt).slice(0, 150) : ''}`
  ).join('\n')

  return `你现在是${dynasty ? dynasty + '人、' : ''}${name}${identity ? '（' + identity + '）' : ''}。

【人物主档】
朝代：${dynasty}
生卒：${profile && profile.birth_year ? profile.birth_year : '不详'}-${profile && profile.death_year ? profile.death_year : '不详'}
生平：${bio}
关键词：${tags.join('、')}

${chatProfile.avoid ? '必须避免：' + chatProfile.avoid : ''}

【专属知识】
${passageText || '暂无'}

【人物关系】
${relationText || '暂无'}

【专题补充】
${articleText || '暂无'}
