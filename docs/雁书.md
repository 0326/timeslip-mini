# 穿越圈 · 雁书功能方案

> 异步慢交互 · 时空漂流信（借鉴旅行青蛙放置等待玩法）

---

## 一、功能概述

**功能名称**：雁书

**核心玩法**：用户书写信笺，选择鸿雁信使送往古代时空，经过等待后收到历史人物回信 + 随机风物特产，形成「投递→等待→收获→收藏」的放置治愈循环。

**Slogan**：一书寄往古时空，鸿雁载信踏云归

**页面结构**：三 Tab 视图
- **雁书**：选鸿雁、选朝代/收信人、写信、发送
- **记录**：旅途中的鸿雁（倒计时进度）、已收信列表
- **藏馆**：风物图鉴，已收藏 / 未解锁

## 二、信使体系

### 2.1 属性总表

| 信使 | 往返时长 | 力量 | 准确率 | 定位 | 核心取舍 |
|------|----------|------|--------|------|----------|
| **轻鸿** | 4小时 | 小 | 80% | 极速短途信使 | 投递快、易送偏、仅带回轻型风物 |
| **归雁** | 12小时 | 中 | 100% | 可靠定向信使 | 定向必达、风物品级中等、精准对话首选 |
| **大雕** | 24小时 | 大 | 90% | 重载长途信使 | 耗时最久、高概率稀有大件、小幅跑偏风险 |

> 开发模式下时长自动缩短为秒级（轻鸿5s / 归雁10s / 大雕15s）便于测试。

### 2.2 信使标签短句（UI展示用）

- **轻鸿**：一日往返 · 载物轻薄 · 偶有迷途
- **归雁**：两日往返 · 定向必达 · 稳妥可靠
- **大雕**：三日往返 · 可负重宝 · 偶会漂流

## 三、玩法规则

### 3.1 收信人选择

用户选择朝代后，系统展示该朝代可选历史人物。朝代列表首项为「随机漂流」选项：

| 选项 | 说明 |
|------|------|
| **随机漂流** | 信使随风漫游，随机匹配历代人物回信，无视准确率 |
| **指定朝代 + 人物** | 指定某位历史人物收信，AI 严格贴合人设回信；准确率生效时可能跑偏 |

### 3.2 准确率判定规则

- **指定人物投递**：
  - 轻鸿：80% 命中目标人物，20% 转为随机漂流
  - 归雁：100% 命中指定人物
  - 大雕：90% 命中目标人物，10% 转为随机漂流
- **随机漂流**：无视准确率，一律随机匹配历史角色

### 3.3 力量与风物对应

| 力量等级 | 风物类型 | 稀有度 |
|----------|----------|--------|
| 小（轻鸿） | 笔墨、笺纸、香膏、点心、铜钱等小型轻便物件 | 普通为主 |
| 中（归雁） | 茶饼、字帖、折扇、玉佩小件、陶罐等中等器物 | 普通~精良 |
| 大（大雕） | 古卷、青铜小件、名家拓片、玉器、古籍残页等厚重珍品 | 精良~稀有~传说 |

### 3.4 风物稀有度

| 等级 | 名称 | 颜色标识 |
|------|------|----------|
| 1 | 普通 | 灰色 |
| 2 | 精良 | 绿色 |
| 3 | 稀有 | 蓝色 |
| 4 | 传说 | 紫色 |

### 3.5 限制规则

- 信笺内容上限 500 字
- 等待期间不可加速，保留期待感
- 未上线期间计时正常走时
- 回信到达后需手动查看详情，领取风物入藏馆

## 四、完整业务流程

```
[雁书 Tab]
选鸿雁信使（左右切换 / 滑动）
    ↓
选收信朝代（含「随机漂流」选项）
    ↓
选收信人（随机漂流时跳过此步）
    ↓
书写笺书（≤500字）
    ↓
点击「鸿雁传书」发送
    ↓
[记录 Tab] 信使启程，开始倒计时
    ↓
等待时长结束，系统实时生成回信 + 风物
    ↓
用户查看回信详情 → 领取风物
    ↓
[藏馆 Tab] 风物存入图鉴永久收藏
    ↓
循环开启下一次投递
```

## 五、AI 回信机制

### 5.1 实时生成

回信在信使到达时**实时生成**（非预生成池），流程：

1. 系统根据收信人物构建 Prompt（包含人设、语气、来信内容）
2. 优先调用真实大模型 API（若配置了 `AI_API_KEY`）
3. API 不可用时使用高质量模板兜底（按人物定制多套模板随机选取）

### 5.2 Prompt 设计要点

- 强制以历史人物身份回复，不得脱离人设
- 文言或半文半白格式
- 回应来信内容，不可泛泛而谈
- 可引用历史典故或名句
- 禁止现代网络词汇

### 5.3 内容安全

所有信笺内容经微信 `msgSecCheck` 安全检测，不合规内容拒绝发送。

## 六、技术实现

### 6.1 云函数

**云函数名**：`yan`

| Action | 说明 |
|--------|------|
| `send` | 发送雁书，创建信件记录 |
| `list` | 获取记录列表（旅行中 + 已收信），自动处理到期信件 |
| `figures` | 获取朝代和人物配置 |
| `carriers` | 获取信使配置 |
| `detail` | 获取信件详情（确保回信已生成） |
| `read` | 标记信件已读 |
| `claim` | 领取风物入藏馆 |
| `collection` | 获取藏馆列表（已收藏 + 未解锁） |

|--------|------|
| `yan_letters` | 雁书记录（含状态、回信、风物） |
| `yan_user_gifts` | 用户藏馆风物 |

## 八、产品差异化亮点

1. **慢节奏放置**：摒弃即时互动，治愈感强，提升用户留存回访
2. **全虚拟交互**：全部交互对象为虚拟历史人物，无 UGC 陌生人社交，降低备案与审核风险
3. **藏品长线激励**：风物收集机制形成长期目标，提升复访频次
4. **快慢互补**：与主产品「笺书（即时私聊）」形成快慢节奏互补，丰富产品体验
5. **随机漂流**：随机匹配机制增加惊喜感，降低选择负担
6. **实时AI回信**：每次回信实时生成，避免预生成池的内容重复问题

## 九、部署上线清单

### 9.1 数据库初始化（必做）

雁书依赖两个集合，**未创建会导致所有读写报 `collection not exists`**：

| 集合名 | 建议权限 | 说明 |
|--------|----------|------|
| `yan_letters` | 仅创建者可读写 | 雁书记录（前端不直连，均经云函数操作） |
| `yan_user_gifts` | 仅创建者可读写 | 用户藏馆风物 |

创建方式（二选一）：
1. 云开发控制台 → 数据库 → 手动新建上述两个集合
2. 部署并调用一次 `initDB` 云函数（`COLLECTIONS` 已包含这两个集合名）

### 9.2 云函数部署

1. 右键 `cloudfunctions/yan` →「上传并部署：云端安装依赖」
2. 确认 `config.json` 已生效：`timeout: 60`、`runtime: Nodejs18.15`、`permissions.openapi: security.msgSecCheck`
3. 部署 `initDB` 并执行一次以初始化集合（若走方式 2）

### 9.3 AI 回信配置（可选）

未配置时使用内置高质量模板兜底，功能完整可用。配置真实大模型后在云函数环境变量中添加：

| 环境变量 | 说明 |
|----------|------|
| `AI_API_KEY` / `DOUBAO_API_KEY` | 大模型 API Key |
| `AI_API_URL` / `DOUBAO_API_URL` | Chat Completions 接口地址 |
| `AI_MODEL` | 模型名（默认 `doubao-pro-32k`） |

> AI 调用限时 8 秒，超时自动回退模板，不会导致云函数超时失败。

### 9.4 开发模式（调试用）

设置环境变量 `YAN_DEV=1` 后，信使时长缩短为秒级（轻鸿5s / 归雁10s / 大雕15s），便于真机验证完整流程。**上线前务必移除。**

### 9.5 冒烟验收路径

1. 发现页 → 雁书 → 选信使 / 朝代 / 收信人 → 写信 →「鸿雁传书」发送成功
2. 「随机漂流」朝代可发送（无收信人选择步骤）
3. 记录 Tab 出现旅途中卡片，倒计时正常走时
4. （开发模式）倒计时结束后刷新列表 → 出现回信卡片 + 未读红点
5. 点开回信 → 详情弹窗内容完整 →「收入藏馆」成功
6. 藏馆 Tab 出现对应风物，统计数字更新
7. 未读角标在查看详情后消除

### 9.6 已知约束

- 回信在用户打开列表 / 详情时触发实时生成（非定时任务），若生成中并发请求会通过状态锁（`processing`）去重，2 分钟超时自动回滚重试
- 单用户信件查询上限 100 条 / 次，藏馆上限 200 件
- 信笺内容经 `msgSecCheck` 检测，违规内容拒绝发送（返回 code 403）
